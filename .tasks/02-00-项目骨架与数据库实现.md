# 最终目标

一个本地运行的应用，用户可以持久性地保存一些 BeatLeader 玩家、歌单，也可以临时性地输入谱面的 key ，然后用户就能查看指定玩家对谱面的游玩情况。

# 本次目标

搭建项目骨架，实现数据库 schema。

# 具体任务

1. 初始化 Tauri 项目
2. 配置 SQLite 数据库
3. 实现 6 张表的 schema（Map、MapDiff、PlayerInfo、PlayerScore、Playlist、PlaylistMap）
4. 编写 Rust 数据库操作模块基础结构

# 任务总结

## 操作罗列

1. **初始化 Tauri 项目**
   - 创建 `package.json`、`tsconfig.json`、`vite.config.ts` 等前端配置文件
   - 创建 `src/main.tsx`、`src/App.tsx`、`src/App.css` 前端入口文件
   - 创建 `src-tauri/Cargo.toml`、`tauri.conf.json` Tauri 配置文件
   - 使用 Python PIL 创建应用图标，通过 `cargo tauri icon` 生成各平台图标

2. **配置 SQLite 数据库**
   - 在 `Cargo.toml` 中添加 `rusqlite` 依赖（bundled 特性）
   - 创建 `src-tauri/src/database/mod.rs` 数据库初始化模块

3. **实现 6 张表 schema**
   - 在 `src-tauri/src/database/schema.rs` 中定义 `create_tables` 函数
   - 实现 Map、MapDiff、PlayerInfo、PlayerScore、Playlist、PlaylistMap 六张表
   - 创建必要索引以优化查询性能

4. **编写 Rust 数据库操作模块**
   - 在 `src-tauri/src/database/operations.rs` 中定义数据结构
   - 实现难度值转换函数 `difficulty_from_value`、`difficulty_to_value`
   - 实现 `parse_leaderboard_id` 解析函数

## 流程归纳

1. 手动创建 Tauri + React + TypeScript 项目骨架（因 create-tauri-app 不支持非交互模式）
2. 使用 Python PIL 生成临时图标，通过 Tauri CLI 生成各平台所需图标
3. 按照数据库设计文档实现完整的 schema 和数据结构

## 结果

- 项目骨架搭建完成，前端与后端均可编译
- 数据库 schema 完整实现 6 张表及必要索引
- 数据结构模块提供了难度转换和 leaderboardId 解析功能
- 数据库文件将存储在 `%APPDATA%/bsr-monitor/bsr_monitor.db`
