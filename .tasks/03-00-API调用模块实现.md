# 最终目标

一个本地运行的应用，用户可以持久性地保存一些 BeatLeader 玩家、歌单，也可以临时性地输入谱面的 key ，然后用户就能查看指定玩家对谱面的游玩情况。

# 本次目标

封装 BeatLeader 和 BeatSaver API 调用模块，为后续业务功能提供基础设施。

# 具体任务

1. 实现 HTTP 客户端基础结构（使用 reqwest）
2. 封装 BeatLeader API：
   - `/player/{id}` - 获取玩家信息
   - `/player/{id}/scores/compact` - 获取玩家成绩（POST, 分页）
   - `/leaderboard/{id}` - 获取排行榜详情
3. 封装 BeatSaver API：
   - `/maps/id/{id}` - 通过 key 获取谱面信息
   - `/maps/hash/{hash}` - 通过 hash 获取谱面信息
   - `/playlists/id/{id}/{page}` - 获取歌单详情
4. 定义 API 响应的数据结构
5. 添加错误处理和重试机制

# 本次任务完成记录

## 操作罗列

1. 在 `Cargo.toml` 中添加依赖：
   - `reqwest` (HTTP 客户端，带 json feature)
   - `tokio` (异步运行时，rt-multi-thread, macros)
   - `thiserror` (错误处理)
2. 创建 `src/api/` 模块结构：
   - `mod.rs` - 模块导出
   - `client.rs` - HTTP 客户端基础结构
   - `error.rs` - 错误类型定义
   - `types.rs` - 共享类型 (Metadata)
   - `beatleader.rs` - BeatLeader API 数据结构与封装
   - `beatsaver.rs` - BeatSaver API 数据结构与封装
3. 实现 HTTP 客户端基础结构：
   - 配置默认超时 (30秒)
   - 设置 User-Agent
   - BeatLeader API 基础 URL: `https://api.beatleader.xyz`
   - BeatSaver API 基础 URL: `https://api.beatsaver.com`
4. 定义 BeatLeader API 数据结构：
   - `PlayerResponse` - 玩家信息
   - `CompactScoreResponseWithMetadata` - 成绩列表响应
   - `CompactScore` / `CompactLeaderboard` - 成绩与排行榜紧凑信息
   - `LeaderboardResponse` - 排行榜详情
5. 定义 BeatSaver API 数据结构：
   - `MapDetail` / `MapDetailMetadata` / `MapStats` / `MapVersion` / `MapDifficulty` - 谱面信息
   - `PlaylistPage` / `PlaylistFull` / `PlaylistStats` - 歌单信息
   - `UserDetail` - 用户信息
6. 实现 BeatLeader API 封装：
   - `get_player(player_id)` - 获取玩家信息
   - `get_player_scores(player_id, page, count)` - 获取玩家成绩 (POST)
   - `get_leaderboard(leaderboard_id)` - 获取排行榜详情
7. 实现 BeatSaver API 封装：
   - `get_map_by_key(key)` - 通过 key 获取谱面
   - `get_map_by_hash(hash)` - 通过 hash 获取谱面
   - `get_playlist(playlist_id, page)` - 获取歌单详情
8. 添加错误处理和重试机制：
   - `ApiError` 枚举：Http, JsonParse, ApiStatus, RateLimited, Timeout, NotFound
   - `request_with_retry` 方法：最多 3 次重试，超时重试延迟 1 秒，429 重试延迟 5 秒

## 流程归纳

### 模块结构

```
src/api/
├── mod.rs          # 模块入口，导出公共类型
├── client.rs       # ApiClient (HTTP 客户端，重试逻辑)
├── error.rs        # ApiError (错误类型)
├── types.rs        # Metadata (分页元数据)
├── beatleader.rs   # BeatLeaderApi + 响应数据结构
├── beatsaver.rs    # BeatSaverApi + 响应数据结构
```

### API 封装设计

每个 API 封装使用 `ApiClient` 进行 HTTP 请求，通过 `request_with_retry` 实现自动重试：

- 超时错误：延迟 1 秒后重试
- 429 (Rate Limited)：延迟 5 秒后重试
- 其他错误：直接返回

### 数据结构设计

数据结构字段使用 `#[serde(default)]` 处理可选/缺失字段，确保反序列化不会因字段缺失失败。
