# 09-02 - 前端稳定性修复

## 优先级：P0-P1

## 背景

## 具体任务

### 1. 进度事件 task_id 过滤（P0）

**1.1 后端返回 task_id**

- [ ] `add_player` 命令返回值从 `Result<(), String>` 改为 `Result<String, String>`，返回生成的 `task_id`
- [ ] `add_playlist` 命令同样处理

**1.2 前端使用 task_id 过滤**

- [ ] `Players.tsx` 中 `handleAddPlayer`：
  - invoke 后获取后端返回的 `task_id`
  - 进度事件监听器中同时校验 `task_type === 'add_player' && payload.task_id === currentTaskId`
  - 不再依赖闭包捕获的 `addForm.id` 作为唯一标识
- [ ] `Playlists.tsx` 中 `handleAddPlaylist` 同样处理

**1.3 Rust 端 task_type 枚举化**

- [ ] `progress.rs` 中 `task_type` 从 `String` 改为 `enum TaskType { AddPlayer, AddPlaylist }`，实现 `Serialize` + `Display`
- [ ] 命令层中硬编码的 `"add_player"` / `"add_playlist"` 字符串替换为枚举

### 2. 页面刷新后 loading 状态丢失（P0）

**2.1 后端维护任务状态**

- [ ] 在 Tauri state 中维护一个 `HashMap<String, TaskStatus>` 记录正在执行的任务（task_id → {task_type, target_id, progress}）
- [ ] 任务开始时注册，结束时移除
- [ ] 新增命令 `get_active_tasks` 返回当前进行中的任务列表

**2.2 前端恢复 loading 状态**

- [ ] `loadPlayers` 完成后调用 `get_active_tasks`，检查是否有当前玩家的添加任务在进行中
- [ ] 如有，恢复对应玩家条目的 `loading` / `progress` 状态
- [ ] `loadPlaylists` 同样处理

**2.3 删除保护增强**

- [ ] `handleDeletePlayer` 中增加后端校验：调用 `get_active_tasks` 检查该玩家是否正在被添加，如有则拒绝删除
- [ ] `handleDeletePlaylist` 同样处理

### 3. Error Boundary（P1）

- [ ] 创建 `src/components/ErrorBoundary.tsx` 类组件（Error Boundary 必须是 class component）
- [ ] 在 `App.tsx` 中用 ErrorBoundary 包裹整个应用路由
- [ ] 捕获未处理的 React 错误后展示降级 UI（错误信息 + 重新加载按钮）
- [ ] 可选：将错误日志发送到 Tauri 后端记录

### 4. Audio 实例泄漏修复（P1）

**4.1 全局 Audio 管理器**

- [ ] 重构 `AudioContext`（`src/contexts/AudioContext.tsx`），从仅管理 `volume` 扩展为管理全局单例 `Audio` 对象
- [ ] 提供 `playPreview(url: string)` 和 `stopPreview()` 方法
- [ ] 播放新音频时自动停止当前播放并切换 `src`，复用同一 Audio 实例

**4.2 更新 CoverWithAudio 组件**

- [ ] `CoverWithAudio.tsx` 改为使用 AudioContext 的 `playPreview` / `stopPreview`，不再创建 `new Audio()`
- [ ] 移除组件内部的 Audio 对象创建和 cleanup 逻辑
- [ ] cleanup 中 `audio.src = ''` 的问题已在全局管理器中解决（不再需要此操作）

**4.3 持久化音量设置**

- [ ] 使用 `localStorage` 持久化用户音量设置
- [ ] `AudioProvider` 初始化时从 localStorage 读取上次保存的音量
- [ ] 音量变化时自动保存到 localStorage

### 5. 进度事件监听器生命周期修复（P1）

- [ ] `Players.tsx` 中进度事件监听器从 `handleAddPlayer` 内部移至 `useEffect` 中管理
- [ ] 组件卸载时确保 `unlisten` 被调用，防止内存泄漏
- [ ] `Playlists.tsx` 同样处理

### 6. `formatRating` 修复（P1）

- [ ] `src/utils/format.ts` 中 `formatRating`：将 `if (!rating)` 改为 `if (rating == null)`（仅排除 undefined/null，不排除 0）

### 7. 歌单切换时 playlistMaps 清空（P1）

- [ ] `Playlists.tsx` 中 `handleViewMaps`：在打开新歌单前先 `setPlaylistMaps([])` 清空旧数据
- [ ] 或在关闭弹窗时清空 `playlistMaps`

## 验收标准

1. 同时添加多个不同玩家时，各任务的进度事件不互相干扰
2. 页面刷新后，后台仍在进行的任务在前端恢复 loading 状态
3. 删除正在处理中的玩家/歌单被后端拒绝
4. 模拟 React 错误时应用展示降级 UI 而非白屏
5. 歌单模式下快速滚动不再创建大量 Audio 对象
6. 音量设置在应用重启后保持
