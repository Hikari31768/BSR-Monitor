# 09-05 - 性能优化

## 优先级：P2

## 背景

08-06（打谱查询）、08-07（玩家管理）Review 中发现的性能问题，包括缺少 memo、N+1 调用、批量操作效率低。

## 具体任务

### 1. 前端 React 性能优化

**1.1 useMemo 包裹重复计算**

- [ ] `ScoreTable.tsx:188`：`sortedPlayers` 用 `useMemo` 包裹，依赖 `[selectedPlayers]`
- [ ] `ScoreTable.tsx:183-185`：`displayData` 用 `useMemo` 包裹，依赖 `[currentMapData, playlistData, viewMode]`
- [ ] `MapScoreGroup.tsx:54`：`gridColumns` 字符串计算改为 `` `18rem 6rem ${'7rem '.repeat(players.length).trim()} 7rem` `` 或 `useMemo`
- [ ] `ScoreTableHeader.tsx:41`：同样的 `gridColumns` 问题

**1.2 useCallback 包裹事件处理**

- [ ] `ScoreTableHeader` 的 `handleDragStart` / `handleDragOver` / `handleDragEnd` 用 `useCallback` 包裹
- [ ] `ScoreTable.tsx` 中 `searchMap` 的 `useCallback` 依赖数组优化：将 `selectedPlayers` 从依赖中移除，使用 `useRef` 获取最新值

**1.3 useEffect 拆分**

- [ ] `ScoreTable.tsx:148-152`：依赖 `[currentPage, viewMode, selectedPlaylistId, searchPlaylist]` 的 effect 拆分为两个：
  - effect A：仅监听 `currentPage`，当页码变化时触发查询
  - effect B：监听 `viewMode` / `selectedPlaylistId` / `selectedPlayers`，当查询条件变化时重置页码并触发查询

**1.4 查询防抖与竞态防护**

- [ ] `ScoreTable.tsx` 歌单切换的 useEffect 中添加竞态防护：使用 `AbortController` 或 cleanup 标志防止旧请求覆盖新结果
- [ ] 歌单切换时添加防抖（300ms），避免频繁切换产生的请求风暴

### 2. 后端批量操作优化

**2.1 玩家分数统计批量接口**

- [ ] 新增 Rust 命令 `get_players_with_score_counts`：一次返回所有玩家及其分数统计
- [ ] SQL：`SELECT p.*, COUNT(ps.playerId) as score_count FROM player_info p LEFT JOIN player_score ps ON p.id = ps.playerId GROUP BY p.id`
- [ ] 更新 `Players.tsx` 中 `loadPlayers`：用单次 invoke 替代 1+N 次调用

**2.2 `update_player_scores` 批量优化**

- [ ] `score.rs:474-508`：循环内每条成绩都 `get_score_by_pk` + `insert_score`，各有一次锁获取
- [ ] 改为：批量查询已存在记录（`SELECT * FROM player_score WHERE (playerId, hash, mode, difficulty) IN (...)`）
- [ ] 批量插入新记录或使用事务包裹循环

**2.3 `add_new_player` 全量拉取批量插入**

- [ ] `player.rs:128-130`：全量拉取成绩时逐条 `insert_score`
- [ ] 改为：先在内存中构建所有 `PlayerScore` 记录，然后通过单条事务批量插入

**2.4 `save_playlist_maps_with_progress` 锁优化**

- [ ] `playlist.rs:263-298`：每个谱面的 Map、MapDiff、PlaylistMap 分别获取/释放锁
- [ ] 合并为一次事务：在事务内完成 Map 插入 → MapDiff 批量插入 → PlaylistMap 插入

### 3. 其他优化

**3.1 `get_map_by_hash` 缓存检查**

- [ ] `get_map_by_hash` 命令中先检查数据库是否已有该 hash 对应的谱面
- [ ] 如已存在则直接返回，避免重复 API 调用

**3.2 `PlayerSelectModal` 玩家列表复用**

- [ ] `PlayerSelectModal` 每次打开都重新调用 `get_player_list`
- [ ] 改为通过 props 传入已有的玩家列表，由父组件管理

**3.3 废弃文件删除**

- [ ] `src/components/ScoreRow.tsx`：无任何地方 import，为废弃代码，删除
- [ ] `src/components/NoScoreMapRow.tsx`：同上，删除
