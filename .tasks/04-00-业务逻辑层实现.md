# 最终目标

一个本地运行的应用，用户可以持久性地保存一些 BeatLeader 玩家、歌单，也可以临时性地输入谱面的 key ，然后用户就能查看指定玩家对谱面的游玩情况。

# 本次目标

实现业务逻辑层，整合 API 和数据库模块，提供核心功能接口。

# 具体任务

1. 创建 `src/business` 模块结构
2. 实现玩家管理：
   - 添加玩家（调用 API 获取信息，存入数据库）
   - 查询玩家列表
   - 删除玩家
3. 实现成绩管理：
   - 全量拉取玩家成绩（添加玩家时）
   - 增量更新成绩（按时间倒序，遇到已存在则停止）
   - 查询玩家成绩
4. 实现谱面管理：
   - 通过 key/hash 获取谱面信息
   - 查询谱面详情
5. 实现歌单管理：
   - 添加歌单（获取歌单信息，批量填充谱面）
   - 查询歌单列表
   - 删除歌单
6. 实现排行榜查询：
   - 通过 leaderboardId 获取排行榜详情（含各版本 hash）

# 设计要点

## 模块结构

```
src/business/
├── mod.rs           # 模块入口
├── player.rs        # 玩家管理
├── score.rs         # 成绩管理
├── map.rs           # 谱面管理
├── playlist.rs      # 歌单管理
├── leaderboard.rs   # 排行榜查询
```

## 业务流程

### 添加玩家

1. 调用 `BeatLeaderApi::get_player(id)` 获取玩家信息
2. 存入 `PlayerInfo` 表（包含用户填写的 liveURL、alias）
3. 调用 `BeatLeaderApi::get_player_scores(id, page, 100)` 循环拉取所有成绩
4. 解析 leaderboardId 得到 mapKey（可选）
5. 存入 `PlayerScore` 表，遇到已存在的 `(playerId, hash, mode, difficulty)` 则判断是否更新

### 增量更新成绩

1. 按 page=1 开始，sortBy=date 降序拉取
2. 遍历成绩，检查 `(playerId, hash, mode, difficulty)` 是否已存在
3. 若存在且 epochTime ≤ 本地记录，停止拉取
4. 若存在且 epochTime > 本地记录，更新记录
5. 若不存在，插入新记录

### 添加歌单

1. 调用 `BeatSaverApi::get_playlist(id, 0)` 获取歌单第一页
2. 存入 `Playlist` 表
3. 遍历 maps 数组：
   - 存入 `PlaylistMap` 表（关联关系）
   - 存入 `Map` 表（谱面信息）
   - 存入 `MapDiff` 表（难度信息）
4. 若歌单有更多页面，继续拉取并填充

### 获取谱面

1. 用户输入 key 或 hash
2. 调用 `BeatSaverApi::get_map_by_key` 或 `get_map_by_hash`
3. 存入 `Map` 和 `MapDiff` 表
4. 返回谱面详情

## 数据转换

### leaderboardId 解析

解析 `4b302xx91` 得到：
- key: `4b302`（可能不准确）
- 版本段: `xx`（第 3 版）
- 难度: 9 (ExpertPlus)
- 模式: 1 (Standard)

### 难度值转换

BL API 返回整数，需转换为字符串：
- 1 → Easy
- 3 → Normal
- 5 → Hard
- 7 → Expert
- 9 → ExpertPlus

已在 `database/operations.rs` 中实现 `difficulty_from_value`。
