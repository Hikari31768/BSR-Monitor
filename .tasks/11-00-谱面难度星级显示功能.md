# 谱面难度星级显示功能

## Context

打谱查询页面中，每个谱面的难度列只显示难度徽章（如 `E+`），缺少 BeatLeader 提供的星级数据（如 `10.95★`）。星级数据能直观反映谱面难度，帮助玩家快速评估。需要从 BeatLeader 的 `GET /leaderboards/hash/{hash}` 接口获取，按需加载并缓存到本地数据库。

---

## 改动清单

### 1. 数据库 schema — 为 MapDiff 表添加星级字段

**文件**: `src-tauri/src/database/schema.rs`

- `MapDiff` 表新增两列：
  - `starsRating FLOAT` — 星级值（如 8.81、10.95）
  - `starsFetchedAt BIGINT` — 拉取时间的 epoch（0 表示未拉取）
- `schema.rs` 的 `create_tables` 函数改为：先 `CREATE TABLE IF NOT EXISTS` 再 `ALTER TABLE ADD COLUMN IF NOT EXISTS`（兼容已有数据库）

### 2. 数据库 operations — 星级读写操作

**文件**: `src-tauri/src/database/operations.rs`

在 `MapDiff` struct 和 CRUD 中新增：
- `MapDiff` struct 添加 `stars_rating: Option<f32>` 和 `stars_fetched_at: Option<i64>` 字段
- `insert_map_diffs_batch` 的 INSERT 语句增加 `starsRating` 和 `starsFetchedAt`
- 新增函数 `get_hash_without_stars(conn, hashes: &[String]) -> Vec<String>`：
  - 返回已存入 MapDiff 但尚未拉取星级的 hash 列表
- 新增函数 `update_diff_stars(conn, hash, mode, difficulty, stars)`：按 (hash, mode, difficulty) 更新星级
- `get_map_diffs_by_key` 的 SELECT 增加 `starsRating, starsFetchedAt`

### 3. BeatLeader API — 新增 hash 批量查询接口

**文件**: `src-tauri/src/api/beatleader.rs`

新增 struct 和 API 方法：

```rust
// 响应结构
pub struct LeaderboardsByHashResponse {
    pub leaderboards: Vec<LeaderboardEntry>,
    pub song: SongResponse,
}
pub struct LeaderboardEntry {
    pub id: String,
    pub difficulty: DifficultyResponse,
}
// DifficultyResponse 已有 stars: Option<f32> 需新增

// API 方法
pub async fn get_leaderboards_by_hash(&self, hash: &str) -> Result<LeaderboardsByHashResponse, ApiError>
```

- 请求：`GET https://api.beatleader.xyz/leaderboards/hash/{hash}`
- 解析返回的 `song.difficulties[]`，提取每个难度的 `customDifficultyName`、`difficultyName`、`stars`

### 4. score command — 在查询时按需拉取星级

**文件**: `src-tauri/src/commands/score.rs`

修改 `build_map_scores_response` 函数（这是单谱面和歌单查询的共同入口）：

**流程**（关键：顺序拉取，避免并发）：
1. 从 `all_diffs` 中提取去重后的 hash 列表
2. 调用 `get_hash_without_stars` 找出未拉取星级的 hash
3. 对每个未拉取的 hash，**顺序**调用 BeatLeader API `get_leaderboards_by_hash`
4. 将返回的每个难度星级写入数据库（`update_diff_stars`）
5. 按 (hash, mode, difficulty) 匹配更新 `all_diffs` 中的星级字段
6. 继续构建 `ScoreRowData`，将星级附加到返回数据中

**注意**：`build_map_scores_response` 当前是同步函数，星级拉取是 async 的。需要将其改为 async 或拆分为两步。

**推荐方案**：将拉取逻辑拆为新函数 `fetch_and_store_stars_for_hashes(conn, hashes)`，在 `get_map_scores` 和 `get_playlist_scores` 调用 `build_map_scores_response` **之前**调用。

### 5. 前端类型 — ScoreRowData 增加星级字段

**文件**: `src/types/index.ts`

- `ScoreRowData` 添加 `stars?: number` 字段

### 6. 前端组件 — MapScoreGroup 显示星级

**文件**: `src/components/MapScoreGroup.tsx`

- 难度信息单元格（第 163-174 行）在 `DiffBadge` 旁边显示星级
- 星级文本格式：`X.X★`（保留一位小数），使用 `text-bs-text-muted text-xs` 样式
- 无成绩情况（第 100-103 行）同样显示

### 7. 前端布局 — 难度列加宽 50%

**文件**: `src/components/MapScoreGroup.tsx`

- 第 54 行 `gridColumns` 计算：`6rem` → `9rem`（18rem + **9rem** + players + 空白列）

## 流程归纳

```
用户查询谱面 (key/hash)
  │
  ├→ 获取 MapDiff（含 hash 列表）
  ├→ 筛选未拉取星级的 hash（starsRating IS NULL OR starsFetchedAt IS NULL）
  ├→ 顺序调用 BeatLeader API: GET /leaderboards/hash/{hash}
  │    └→ 解析 song.difficulties[].stars → 写入 MapDiff
  ├→ 重新获取 MapDiff（含星级）
  └→ 构建 ScoreRowData（难度行带 stars 字段）→ 前端渲染
```

## 总结

本次实现在打谱查询页面的难度列旁新增 BeatLeader 星级显示。核心设计是**按需懒加载 + 本地缓存**：首次查询时顺序拉取未缓存 hash 的星级数据并存入数据库，后续查询直接复用，不重复请求外部 API。歌单模式下批量收集所有 hash 后统一拉取，进一步减少 API 调用次数。数据库迁移采用 `ALTER TABLE ADD COLUMN IF NOT EXISTS` 确保向后兼容已有数据库。
