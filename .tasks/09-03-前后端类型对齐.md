### 1. TypeScript 类型定义重构

**1.1 UI 状态与数据模型分离**

- [x] `PlayerInfo`（`src/types/index.ts`）：移除 `loading?`、`progress?`、`status_message?` 字段，保持纯数据模型
- [x] `Playlist`（`src/types/index.ts`）：同样移除 UI 状态字段
- [x] 新增 `PlayerUIState` 接口：`{ loading: boolean; progress: number; statusMessage: string }`
- [x] 新增 `PlaylistUIState` 接口：同上
- [x] 在 `Players.tsx` 中用 `Record<string, PlayerUIState>` 独立管理 UI 状态
- [x] 在 `Playlists.tsx` 中同样处理

**1.2 类型名称统一**

- [x] `ScoreRow`（TS）更名为 `ScoreRowData`，与 Rust 端 `ScoreRowData` 一致
- [x] 同步更新所有引用此类型的文件：`src/components/ScoreTableHeader.tsx`、`src/components/MapScoreGroup.tsx`、`src/types/index.ts`

**1.3 过期类型清理**

- [x] `LeaderboardResponse`（`src/types/index.ts`）：检查是否被任何代码引用，若未引用则删除
- [ ] 若仍被引用，根据实际 API 响应结构重新定义或替换为正确的类型

**1.4 命令层类型对齐**

- [ ] `MapScoresResponse` 中 `no_score_groups` → `no_score_diffs`（TS 端同步）
- [ ] `PlayerScoreCell` 确认是否需要 `is_current_version` 字段，如需则添加到 Rust 和 TS 端
- [ ] 确认 `get_playlist_scores` 命令的 `reverse: bool` 参数是否在前端使用，如不使用则移除

# 本次任务完成记录

## 操作罗列

1. **UI 状态与数据模型分离**
   - 从 `PlayerInfo` 和 `Playlist` 类型中移除 `loading`, `progress`, `status_message` 字段
   - 新增 `PlayerUIState` 和 `PlaylistUIState` 接口在 `src/types/index.ts`
   - 在 `Players.tsx` 中添加 `playerUIStates` 和 `playerTaskIds` state 独立管理 UI 状态
   - 在 `Playlists.tsx` 中添加 `playlistUIStates` 和 `playlistTaskIds` state 独立管理 UI 状态
   - 修改 `PlayerCard.tsx` 接收 `uiState` prop
   - 修改 `PlaylistCard.tsx` 接收 `uiState` prop
   - 使用 ref 存储 taskId 映射，避免 progress 事件监听器频繁重新订阅

2. **类型名称统一**
   - 将 `ScoreRow` 更名为 `ScoreRowData`，与 Rust 端保持一致
   - 更新 `MapScoreGroup.tsx`, `ScoreTableRow.tsx` 中的类型引用

3. **过期类型清理**
   - 删除未使用的 `LeaderboardResponse` 类型

4. **常量提取**
   - 创建 `src/constants/index.ts`，将 `difficultyColors` 和 `modeNames` 移至该文件
   - 在 `src/types/index.ts` 中从 constants 重新导出以保持向后兼容

5. **类型映射文档**
   - 创建 `.project/docs/TypeMapping.md`，记录完整的 Rust ↔ TypeScript 类型映射关系

1. 先修改类型定义（types/index.ts），建立新的类型结构
