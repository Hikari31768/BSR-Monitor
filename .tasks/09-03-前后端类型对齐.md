# 09-03 - 前后端类型对齐

## 优先级：P1（依赖 09-01 完成后执行）

## 背景

08-01、08-03、08-10 Review 中发现的 Rust 端与 TypeScript 端类型不一致、UI 状态混入数据模型等问题。

## 具体任务

### 1. TypeScript 类型定义重构

**1.1 UI 状态与数据模型分离**

- [ ] `PlayerInfo`（`src/types/index.ts`）：移除 `loading?`、`progress?`、`status_message?` 字段，保持纯数据模型
- [ ] `Playlist`（`src/types/index.ts`）：同样移除 UI 状态字段
- [ ] 新增 `PlayerUIState` 接口：`{ loading: boolean; progress: number; statusMessage: string }`
- [ ] 新增 `PlaylistUIState` 接口：同上
- [ ] 在 `Players.tsx` 中用 `Record<string, PlayerUIState>` 独立管理 UI 状态
- [ ] 在 `Playlists.tsx` 中同样处理

**1.2 类型名称统一**

- [ ] `ScoreRow`（TS）更名为 `ScoreRowData`，与 Rust 端 `ScoreRowData` 一致
- [ ] 同步更新所有引用此类型的文件：`src/components/ScoreTableHeader.tsx`、`src/components/MapScoreGroup.tsx`、`src/types/index.ts`

**1.3 过期类型清理**

- [ ] `LeaderboardResponse`（`src/types/index.ts`）：检查是否被任何代码引用，若未引用则删除
- [ ] 若仍被引用，根据实际 API 响应结构重新定义或替换为正确的类型

**1.4 命令层类型对齐**

- [ ] `MapScoresResponse` 中 `no_score_groups` → `no_score_diffs`（TS 端同步）
- [ ] `PlayerScoreCell` 确认是否需要 `is_current_version` 字段，如需则添加到 Rust 和 TS 端
- [ ] 确认 `get_playlist_scores` 命令的 `reverse: bool` 参数是否在前端使用，如不使用则移除

### 2. Rust 端类型调整

**2.1 命令返回值类型**

- [ ] `ScoreRowData`（`commands/score.rs`）：确保所有字段与前端 `ScoreRowData` 完全对应
- [ ] `PlayerScoreCell`：根据 Review 结论决定是否添加 `is_current_version`
- [ ] `MapScoresResponse` / `PlaylistScoresResponse`：字段名统一

**2.2 API 响应结构体完善**

- [ ] 参考 09-01 中添加的 `#[serde(default)]` 更新文档
- [ ] 确保 `serde` 序列化后的字段名与前端期望匹配（snake_case vs camelCase）
- [ ] 如前端期望 camelCase，考虑在 commands 层统一转换或使用 `#[serde(rename_all = "camelCase")]`

### 3. 类型映射文档

- [ ] 在 `.project/docs/API.md` 或新建 `.project/TypeMapping.md` 中记录 Rust ↔ TypeScript 类型对应关系
- [ ] 包含：Rust 结构体 → 命令层返回结构 → 前端 TS 类型的完整映射链
- [ ] 标注哪些字段是自动序列化、哪些需要手动转换

### 4. 常量与配置提取

- [ ] `difficultyColors`（`src/types/index.ts`）：移至 `src/constants/index.ts`
- [ ] `modeNames`（`src/types/index.ts`）：同样移至 `src/constants/index.ts`
- [ ] `difficultyColors` 的值从 Tailwind 类名字符串改为纯 CSS 变量映射（配合 09-06 样式统一）
