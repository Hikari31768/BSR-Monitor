# 最终目标

一个本地运行的应用，用户可以持久性地保存一些 BeatLeader 玩家、歌单，也可以临时性地输入谱面的 key ，然后用户就能查看指定玩家对谱面的游玩情况。

初步打算基于 Tauri 来开发这个应用，轻量、易用。

## 流程归纳

### API 选择

| 用途 | API |
|------|-----|
| 玩家信息 | BL `/player/{id}` |
| 成绩拉取 | BL `/player/{id}/scores/compact` (POST, count=100) |
| 排行榜详情 | BL `/leaderboard/{id}` |
| 谱面信息 | BeatSaver `/maps/id/{id}` 或 `/maps/hash/{hash}` |
| 歌单详情 | BeatSaver `/playlists/id/{id}/{page}` |

### 数据库设计要点

- MapDiff 表使用复合主键 `(key, hash, mode, difficulty)`
- PlayerScore 表使用复合主键 `(playerId, hash, mode, difficulty)`，保证每个难度只保留最高分
- PlayerScore 增加 `scoreId` 字段存储 BL 成绩 ID
- Map 表增加 `songAuthorName`、`levelAuthorName` 字段
- 新增 Playlist 和 PlaylistMap 表用于歌单管理
- `mapKey` 字段保留但可能不准确（非常规模式下），`hash` 是可靠标识

## 总结

确定了 6 张数据表（Map、MapDiff、PlayerInfo、PlayerScore、Playlist、PlaylistMap）的结构和 5 个核心 API。

**leaderboardId 解析规则**：
- 有版本段（含 `x`）：以 `x` 为锚点，向前取 key，向后取难度和模式
- 无版本段：从末尾取模式（1位）、难度（1位），剩余为 key

**数据填充要点**：
- 成绩拉取不连锁补全谱面信息
- PlayerScore 按 epochTime 判断是否更新
- MapDiff 插入前将同 key 的旧记录 isCurrent 改为 false
- PlayerInfo 新增 liveURL、alias 字段（用户手动填写）

详细设计见 [.project/Database.md](../.project/Database.md)。
